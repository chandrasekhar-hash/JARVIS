# J.A.R.V.I.S. Production Deployment & Database Migration Guide

This document specifies the deployment architecture and database migration lifecycle for the J.A.R.V.I.S. Cloud Platform (Phase 8.2).

---

## 1. Database Migration Architecture (`Alembic` + `SQLAlchemy 2.x`)

Database schema evolution is managed strictly by **Alembic** using SQLAlchemy 2.x declarative ORM models (`Cloud/models/orm.py`) as the single source of truth. Zero runtime DDL (`CREATE TABLE IF NOT EXISTS`) operations execute during production application startup.

### File Structure
- `Cloud/alembic.ini`: Main Alembic configuration file.
- `Cloud/alembic/env.py`: Migration environment configuration importing `Base.metadata`.
- `Cloud/alembic/versions/`: Revision scripts directory containing version-controlled DDL changes.
- `Cloud/database/schema_verifier.py`: Startup schema compatibility verifier and pre-stamping legacy validator.
- `Cloud/database/migration_lock.py`: Multi-instance migration concurrency lock manager.

---

## 2. Developer Workflow

To make schema changes during development:

```bash
# 1. Modify SQLAlchemy ORM models in Cloud/models/orm.py

# 2. Generate autogenerated Alembic migration revision script:
PYTHONPATH=Cloud alembic -c Cloud/alembic.ini revision --autogenerate -m "Add new column to cloud_users"

# 3. Review generated revision script under Cloud/alembic/versions/

# 4. Test upgrade & downgrade locally:
PYTHONPATH=Cloud alembic -c Cloud/alembic.ini upgrade head
PYTHONPATH=Cloud alembic -c Cloud/alembic.ini downgrade -1

# 5. Run automated migration test suite:
PYTHONPATH=Cloud python3 -m unittest Cloud/tests/test_alembic_migrations.py

# 6. Commit revision script to version control
```

---

## 3. Production Deployment Workflow

Production application startup **never** automatically runs DDL or `alembic upgrade head`. Schema changes must be applied explicitly during the release pipeline:

```bash
# Step 1: Deploy updated container images to production cluster

# Step 2: Execute migration job before starting new API instances
docker-compose exec cloud-api alembic -c Cloud/alembic.ini upgrade head

# Step 3: Start or rolling-restart Cloud API Gateway instances
```

If a production Cloud API instance is started against an outdated database schema, `SchemaVerifier` halts startup with error:
`PRODUCTION STARTUP HALTED: Database schema revision 'X' does not match expected application revision 'Y'.`

---

## 4. Rollback Procedure

If a deployment failure or schema issue occurs:

```bash
# Step 1: Roll back database schema by 1 revision
docker-compose exec cloud-api alembic -c Cloud/alembic.ini downgrade -1

# Step 2: Redeploy previous application container image
```
